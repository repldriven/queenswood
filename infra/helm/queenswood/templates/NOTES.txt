{{- if and .Values.gateway.enabled .Values.gateway.gcp.enabled }}

Public URL (once the LB + cert provision):
  https://{{ .Values.gateway.host }}

The regional external Application Load Balancer takes 5-10 minutes
to come up. The Certificate Manager certificate transitions
PROVISIONING -> ACTIVE over 15-60 minutes for the first issuance,
once the DNSAuthorization CNAME has propagated.

Check progress:
  kubectl -n {{ .Release.Namespace }} get gateway {{ .Release.Name }}-gateway
  kubectl --context kind-xp-mp get certificate.certificatemanager.gcp.upbound.io \
    queenswood-cert -o jsonpath='{.status.atProvider.managed.state}{"\n"}'

Registrar delegation (once-only):
The Cloud DNS managed zone is provisioned by Crossplane on the xp-mp
management cluster. Read its four nameservers and paste them as NS
records for the `queenswood` subdomain at your registrar:

  just gcp-dns-ns

If the cert sticks on PROVISIONING beyond ~30 min, check the
DNSAuthorization CNAME in Cloud DNS matches the value in
DNSAuthorization.status.atProvider.dnsResourceRecord, and confirm the
NS delegation at the registrar is correct -- all four
ns-cloud-cN.googledomains.com. values must be set.
{{- else if .Values.gateway.enabled }}

Gateway: enabled with host {{ .Values.gateway.host }} (non-GCP path).
For GKE deployments with Certificate Manager + HTTP->HTTPS redirect,
also set --set gateway.gcp.enabled=true.
{{- else }}

Gateway: disabled. Port-forward each Service in a separate terminal
to reach the platform from your host. The SPA pods reverse-proxy
their realm's Keycloak at `/keycloak/*`, so a single port-forward
to each SPA is all you need for sign-in (no separate Keycloak
port-forward).

  kubectl -n {{ .Release.Namespace }} port-forward svc/{{ .Release.Name }}-api-service 8080:8080
{{- if .Values.console.enabled }}
  kubectl -n {{ .Release.Namespace }} port-forward svc/{{ .Release.Name }}-console 8081:{{ .Values.console.port }}
{{- end }}
{{- if .Values.jaeger.enabled }}
  kubectl -n {{ .Release.Namespace }} port-forward svc/{{ .Release.Name }}-jaeger 16686:16686
{{- end }}
{{- if .Values.mail.catcher.enabled }}
  kubectl -n {{ .Release.Namespace }} port-forward svc/{{ .Release.Name }}-mailpit 8025:8025
{{- end }}

Then open:
  http://localhost:8080/scalar       (bank-api OpenAPI)
{{- if .Values.console.enabled }}
{{- if .Values.keycloak.dev.user.username }}
  http://localhost:8081              (console -- sign in as `{{ .Values.keycloak.dev.user.username }}`, the password values-local.yaml sets)
{{- else }}
  http://localhost:8081              (console -- the realm has no user to sign in as; install with -f values-local.yaml for `dev` / `dev`)
{{- end }}
{{- end }}
{{- if .Values.jaeger.enabled }}
  http://localhost:16686             (Jaeger -- pick a service, Find Traces to see spans)
{{- end }}
{{- if .Values.mail.catcher.enabled }}
  http://localhost:8025              (Mailpit -- every invitation email the platform sends)
{{- end }}
{{- if and .Values.console.enabled .Values.jaeger.enabled }}

To watch the platform run for real, use the console's
Sandbox > Scenarios page and read the spans it produces back in Jaeger.
{{- end }}
{{- if eq (include "queenswood.keycloakMode" .) "dev" }}

The bundled Keycloak admin console is reachable through the console
SPA at /keycloak/admin (e.g. http://localhost:8081/keycloak/admin),
credentials `admin` / `admin`. No direct port-forward needed.
{{- end }}

To expose publicly on GKE, set --set gateway.enabled=true
--set gateway.gcp.enabled=true --set gateway.host=<your-host>.
